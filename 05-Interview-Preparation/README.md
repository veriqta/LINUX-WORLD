# Linux Interview Preparation

A public, practical interview and examination center for Linux System Administrators. It trains candidates to explain Linux accurately, operate real systems safely, troubleshoot from evidence, recover from failure, and defend engineering decisions at Junior, Mid-Level and Senior levels.

## Choose a level

| Track | Target candidate | Main proof |
| --- | --- | --- |
| [Junior](Junior-Linux-Interview/) | Entry-level administrator or support engineer | Safe command use, core administration and structured escalation |
| [Mid-Level](Mid-Level-Linux-Interview/) | Independent administrator responsible for services and multiple systems | Cross-domain diagnosis, automation, security, recovery and change ownership |
| [Senior](Senior-Linux-Interview/) | Senior administrator, platform engineer, SRE or infrastructure lead | Architecture, fleet controls, deep failure analysis, incident leadership and trade-offs |

## How to use this database

1. Begin at the level you can perform, not the title you want.
2. Answer aloud before reading the model answer.
3. Reproduce commands in an isolated lab and interpret the output.
4. Complete the practical task without copying a finished solution.
5. Inject one controlled failure and recover it.
6. Record gaps by domain, not only by score.
7. Repeat under time pressure and ask another person to challenge assumptions.

## Answer standard

A strong answer follows this sequence:

1. Clarify the goal, scope and constraints.
2. Explain the Linux mechanism.
3. State expected versus observed behavior.
4. Collect the smallest useful evidence set.
5. Build and test a falsifiable hypothesis.
6. Make a bounded, reversible change.
7. Verify the complete user journey and denied behavior.
8. Explain rollback, security, monitoring and prevention.
9. State uncertainty and escalation criteria.

## Important exam notice

This repository is an independent learning resource. It does not contain leaked exam questions and is not endorsed by a certification vendor. Exam objectives, versions, delivery rules and allowed resources can change. Always compare the study map with the vendor's current official objectives before booking an exam.

## Safety

Use systems you own or are authorized to administer. Run storage, firewall, boot, identity, security and failure exercises only in disposable labs with tested recovery. Never publish credentials, private keys, tokens, personal data or unrestricted logs.
