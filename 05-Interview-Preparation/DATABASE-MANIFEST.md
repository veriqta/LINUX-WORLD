# Linux Interview Database Manifest

This manifest describes the validated contents of the Linux World interview and examination database.

## Database size

| Content | Count |
| --- | ---: |
| Public files | 382 |
| Junior, Mid-Level and Senior core domains | 36 |
| Original answered interview questions | 684 |
| Expanded domain assessment items | 2,284 |
| Original scored practical tasks | 36 |
| Certification mock questions | 500 |
| Certification mock answer explanations | 500 |
| Total candidate assessment items | 3,504 |

The assessment total excludes navigation pages, study plans, evaluator guidance, progress tracking and answer-key headings.

## Assessment formats

- technical questions with model answers;
- concepts and internal mechanisms;
- commands, important options and safe use;
- output and state interpretation;
- incident and troubleshooting scenarios;
- multiple-choice questions with distractor explanations;
- true-or-false corrections;
- scored hands-on labs;
- complete practical examinations;
- timed mock interviews;
- behavioral and ownership questions;
- certification-specific mock examinations;
- evaluator rubrics and readiness gates.

## Technical coverage

- Linux architecture, distributions, kernel and user space
- command line, documentation, files and text processing
- users, groups, sudo, PAM, permissions and ACLs
- processes, signals, jobs, systemd, boot and recovery
- packages, repositories, software builds and configuration
- disks, partitions, LVM, RAID, filesystems, mounts and swap
- networking, routing, sockets, DNS, SSH, firewalls and packet analysis
- logging, journald, time synchronization and evidence timelines
- CPU, memory, NUMA, IO, pressure, saturation and capacity
- Bash, Python, scheduling, testing and safe automation
- SELinux, AppArmor, capabilities, auditing and host hardening
- backup, restore, RPO, RTO and disaster recovery
- containers, namespaces, cgroups and host integration
- observability, SLOs, error budgets and alerting
- fleet management, configuration governance and safe delivery
- distributed-system failure behavior on Linux
- incident command, postmortems, architecture and leadership

Official certification objectives remain authoritative. The database contains original preparation material and no leaked examination content.

## Quality rule

An item is not considered mastered because its answer was read. Mastery requires explanation without notes, safe reproduction in a disposable lab, independent verification, controlled failure, recovery and a statement of limitations.
