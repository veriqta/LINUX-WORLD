# Lab Solutions

Solutions explain reference reasoning after a documented attempt. They are not shortcuts and may not be the only correct approach.

## Rules for use

1. Record an attempt and evidence before opening a solution.
2. Use progressive hints first.
3. Compare safety, reasoning, verification and cleanup, not only commands.
4. Rebuild the solution without copying it line by line.
5. Explain an alternative and its trade-offs.

## Required solution contents

- Stable Lab ID and compatible lab version
- Root or design reasoning
- Commands and configuration with explanations
- Representative expected output
- Acceptance-test evidence
- Security and reliability implications
- Common wrong approaches and why they fail
- Alternative valid approaches
- Cleanup and extension exercises

Solutions must never contain real credentials, private infrastructure details or unsafe instructions without isolation guards.
