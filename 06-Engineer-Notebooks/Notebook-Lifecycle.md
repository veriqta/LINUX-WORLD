# Notebook Lifecycle

This standard governs a record from creation through retirement.

## States

| State | Meaning | Required action |
| --- | --- | --- |
| Draft | Work is being prepared | Assign an owner, classification and record ID |
| Active | Work or investigation is in progress | Timestamp actions and preserve evidence |
| Blocked | Progress requires a decision, access or dependency | Record blocker, impact, owner and next review |
| Complete | Outcome and verification are recorded | Complete review, redaction and follow-up ownership |
| Superseded | A newer record replaces this one | Link both records; preserve history |
| Archived | Retention rules require read-only preservation | Restrict access and protect integrity |
| Disposed | Authorized retention period ended | Record disposition approval in the system of record |

## Lifecycle controls

1. Select the narrowest suitable notebook and create a copy.
2. Assign a unique ID, UTC timestamps, owner, classification and authoritative ticket link.
3. Record authorization and a recoverable before state before material action.
4. During work, separate observation, inference, decision and action.
5. At closeout, verify the intended outcome, negative cases, security, monitoring and rollback state.
6. Assign every unresolved risk and follow-up to an owner and due date.
7. Obtain review appropriate to risk, then mark the record complete.
8. Apply retention, access, legal-hold and disposal requirements from the governing organization.

A notebook is not complete because the command succeeded. It is complete when the final state is proven and remaining risk is owned.
