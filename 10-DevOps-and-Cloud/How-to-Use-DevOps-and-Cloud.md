# How to Use DevOps and Cloud

Choose a domain based on the operating responsibility, not a product name. Read Foundations first, then study the Linux layer beneath the selected platform.

## Study workflow

1. Understand the architecture and responsibility boundary.
2. Build a disposable environment.
3. identify users, processes, files, network and storage.
4. Execute a bounded change.
5. Verify desired, effective and runtime state.
6. Cause and recover one controlled failure.
7. Record evidence and explain the remaining risk.

## Operational workflow

Use versioned desired state, peer review, a read-only plan or dry run, bounded concurrency, representative canaries, independent health gates, abort thresholds and a tested recovery method.
