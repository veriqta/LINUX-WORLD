# Glossary Entry Standard

## Required structure

```markdown
## Term

**Definition:** One precise explanation.

**Why it matters:** Operational relevance.

**Inspect safely:** Read-only command, file, or documentation entry.

**Common confusion:** A likely misconception.

**Related terms:** Closely connected glossary entries.
```

## Writing rules

- Define the Linux meaning before broader meanings.
- Expand acronyms on first use.
- Separate stable concepts from implementation details.
- Name distributions or versions when behavior differs.
- Avoid circular definitions.
- Never prescribe a destructive command as an inspection step.
- Link to deeper Linux World material instead of turning the definition into a tutorial.
