# How to Read Technical Documentation

## Before reading

Write the exact question, component, version, distribution, environment, and desired state. Broad searches create broad and often misleading answers.

## During reading

- Confirm that the page belongs to the responsible project or vendor.
- Check the version selector and publication or update date.
- Follow definitions and prerequisites before copying procedures.
- Read warnings, defaults, return values, configuration precedence, and examples.
- Open linked references when a term changes the safety or meaning of a step.

## Convert documentation into action

Create a plan with before-state capture, commands, expected outputs, failure conditions, verification, rollback, and cleanup. Test it in a matching lab.

## When documentation disagrees with the system

Check package version, downstream patches, configuration precedence, environment variables, aliases, shell builtins, enabled features, and whether a restart or reload is required. Record the discrepancy with reproducible evidence.
