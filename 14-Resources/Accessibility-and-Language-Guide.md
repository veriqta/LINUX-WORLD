# Accessibility and Language Guide

Linux World should be usable across devices, languages, abilities, and connection speeds.

## Accessibility checks

- Use descriptive link text instead of raw URLs where practical.
- Keep headings hierarchical and tables understandable outside visual layout.
- Provide text alternatives for diagrams and screenshots.
- Prefer videos with accurate captions, readable terminals, and transcripts.
- Identify flashing content, poor audio, low contrast, or tiny terminal text.
- State when a resource requires JavaScript, registration, high bandwidth, or payment.
- Avoid relying on color alone to express status.

## Language records

Record the teaching language, subtitle languages, transcript availability, translation owner, and last language review. Machine-generated subtitles should be labeled because technical terms are often mistranscribed.

## Translation quality

Technical translations must preserve commands, paths, option names, error messages, product names, and code exactly. Review key safety warnings with a fluent technical speaker before recommendation.

## Low-bandwidth alternatives

Where possible, pair video with documentation, transcripts, downloadable examples, or local manual pages. Do not assume continuous high-speed internet access.
