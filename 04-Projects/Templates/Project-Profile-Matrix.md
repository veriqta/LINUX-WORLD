# Project Profile Matrix

A higher level means more learner-owned decisions, not missing documentation or untestable requirements.

| Component | Junior | Mid-Level | Senior | Capstone |
| --- | --- | --- | --- | --- |
| Scenario | Complete | Complete | Competing constraints | Stakeholders and milestones |
| Environment | Exact steps | Baseline with choices | Constraints and automation contract | Multi-component plan |
| Commands | Fully explained | Important and risky commands explained | Reference commands | Integration controls |
| Implementation | Line-by-line core work | Guided decision points | Requirements and patterns | Milestone contracts |
| Starter code | Nearly complete | Functional skeleton | Interfaces and controls | Integrated scaffolding |
| Solution | Complete | Complete comparison | Architecture and components | Staged or maintainer reference |
| Tests | Supplied and explained | Supplied plus extensions | Required suites | Cross-component gates |
| Failure work | Safe isolated failures | Dependent failures | Game days | End-to-end scenarios |
| Evidence | Guided checklist | Requirement mapping | Risk and SLO mapping | Review board package |

## Required files

| Template | Junior | Mid-Level | Senior | Capstone |
| --- | :---: | :---: | :---: | :---: |
| README, brief, prerequisites, environment, architecture | Required | Required | Required | Required |
| Implementation, troubleshooting, tests, runbook, cleanup, portfolio | Required | Required | Required | Required |
| Step-by-step guide and commands explained | Required | Recommended | Optional | Optional |
| Threat model and ADRs | Basic | Required | Required | Required |
| Objectives and backup/recovery | When applicable | Required | Required | Required |
| Failure lab | Required | Required | Game day | Multiple game days |
| Postmortem, evidence register, assessment | Recommended | Required | Required | Required |
