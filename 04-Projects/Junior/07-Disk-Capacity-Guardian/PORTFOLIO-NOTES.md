# Disk Capacity Guardian: Portfolio Notes

## Public statement

Build a service that detects block and inode pressure, reports largest growth areas, and produces safe operator guidance without deleting data automatically.

## Evidence to include

- Architecture diagram
- Sanitized configuration excerpts
- Installation or automation code
- Test matrix and results
- Failure and recovery narrative
- Security evidence
- Health or monitoring output
- Cleanup verification
- One decision record

## Interview discussion

Explain the problem, architecture, Linux mechanisms, hardest failure, security trade-off, verification method, and what changes at production scale.

## Honest measurements

Measure setup time, test count, recovery time, report size, backup duration, resource use, or detection time. State environment and method.

## Redaction

Remove real usernames, addresses, hostnames, keys, tokens, account data, internal paths, customer information, serial numbers, and unrestricted logs.

## Reviewer standard

A reviewer should understand the problem, reproduce the build, see proof of tests, identify limitations, and understand operation and cleanup.
